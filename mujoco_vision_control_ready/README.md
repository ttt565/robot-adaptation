# MuJoCo 视觉与运动线索参与控制

本页路径相对于仓库根目录。命令示例从仓库根目录的 CMD 开始；第一次 cd 进入本阶段目录。依赖安装见[仓库说明](../README.md)。

这个版本让相机识别结果实际参与机器人速度限制，并用三组控制对照检查效果。三组始终跟踪原来按时间定义的同一参考轨迹；不会给减速组重新放慢参考时钟。

这是用于验证假设的实验控制器。已完成的对照表明，限速减少了轮车速度差，但增大了对原时间轨迹的误差；当前不能把它当作优于原控制的方法。

## 运行

打开 `mujoco_vision_control_ready`，双击 `start_control.cmd`。启动器优先使用上一级目录的 `.venv\Scripts\python.exe`，找不到时调用命令行中的 `python`；不安装依赖或更改系统设置。

在已经激活原虚拟环境的 CMD 中也可运行：

```cmd
cd /d mujoco_vision_control_ready
python run_control.py
```

双击 `compare_control.cmd`，会比较三个控制策略、全部五个场景和种子 0、1：

```cmd
python run_control.py --compare --all-cases --seeds 0 1
```

对照运行不打开交互窗口，但仍离屏渲染车载相机图像。仿真与图像处理可能明显慢于实际时间；请以终端输出为准。完整可用参数请查看 `python run_control.py --help`。

## 三组控制的区别

| 组别 | 速度限制依据 |
|---|---|
| `baseline` | 原动力学自适应控制，不根据诊断线索主动限速 |
| `motion_only` | 仅根据持续的运动异常或滑移线索限速 |
| `vision_motion` | 视觉外观变化触发短暂谨慎限速，同时结合运动异常或滑移线索 |

视觉外观变化只触发约 1 秒的谨慎阶段，不能仅凭外观持续判定低摩擦。运动或滑移线索需要持续满足条件才能触发；是否延长限制由相应线索决定。相机观测产生的控制变化从下一控制步开始生效，不使用尚未拍摄的图像。

这些是保守的速度调节规则，不是摩擦系数估计或故障确诊。湿暗或纹理变化不必然影响抓地力；电机故障和不可见路况也可能产生相似的运动残差。

上限约束的是控制器的速度目标，实测速度可能因惯性和控制延迟暂时超出。进入谨慎状态时会先去掉高于当前观测速度的闲置上限余量，因此上限曲线不具有全程严格的下降斜率界；随后按设置平滑降低和恢复。

## 如何判断有没有帮助

`position_rmse` 始终相对于原时间参考轨迹计算。减速可能减少打滑，却增加位置误差并损失前进进度；不能通过改变参考轨迹或只挑选一个滑移指标来证明控制改善。

应同时查看轨迹误差、前进进度、滑移线索、速度限制持续时间和控制输入，并将视觉加运动组与仅运动组比较，判断相机是否提供了额外作用。只换外观但摩擦不变的场景尤其有用：视觉谨慎限速可能产生代价，应把这部分结果保留。

每组使用同一条原参考轨迹，但闭环状态、控制输入会不同，不能把跨组预测误差当作同一日志上的模型优劣。提前关闭实时窗口会保存已运行数据并标记 `complete=false`；部分结果不能当作完整实验成绩。

## 图像、记录与模型范围

无窗口对照仅保存每次运行的首末 RGB 图像，全部 5 Hz 相机识别结果仍写入 CSV。程序会打印输出目录，请同时保留机器人日志、诊断记录与汇总指标，检查速度变化是否发生在相机或运动线索出现之后。

外观分类器识别模拟网格、颗粒和平行条纹。当前独立测试集 30 张中有 29 张正确、1 张拒识为未知；这只是模拟纹理结果，不表示能够识别真实道路材料。运行时分类器仅输入 RGB，真实摩擦与场景标签用于仿真和评分。

本版本仍需要 MuJoCo 图形渲染环境，离屏运行也不等于无需 OpenGL。若启动失败，请保留终端完整报错，并确认使用原项目虚拟环境。

## 已验证结果与失败模式

固定控制参数后，另外使用种子 2、3，各运行五个场景和三组控制，共完成 30 次完整的 18 秒实验。以下是这两个新种子的描述性结果，不代表稳健统计结论或训练泛化证明；汇总见 `sample_results/comparison_seed_2.json`、`sample_results/comparison_seed_3.json`，原始记录分别在 `sample_results/seed_2`、`sample_results/seed_3`。

外观与低摩擦同时变化时，两个种子的平均结果为：

| 控制组 | 原时间参考位置 RMSE（米）↓ | 末时刻前进进度（米）↑ | 平均轮体速度差（米/秒）↓ |
|---|---:|---:|---:|
| `baseline` | 1.74549 | 9.84608 | 3.08600 |
| `motion_only` | 2.86310 | 7.54995 | 0.11481 |
| `vision_motion` | 2.84404 | 7.57948 | 0.10163 |

限速明显减小了轮周速度与车体速度不一致的线索，但同时增加原时间参考下的位置误差、损失前进进度。视觉加运动组相对仅运动组的两种子平均改善很小，且收益不稳定：种子 3 的位置 RMSE 反而为 2.90180 米，高于仅运动组的 2.87275 米。这里的轮体速度差只是滑移线索，不是标准滑移率。

只改变外观、摩擦不变时，视觉谨慎控制的位置 RMSE 为 0.03049 米，高于基线的 0.00778 米；末时刻进度几乎补回，但中途跟踪仍付出了代价。

电机故障是当前规则的明确失败模式：原动力学自适应基线的位置 RMSE 为 0.01872 米，加入运动或视觉加运动限速后都增至 1.75833 米。预测异常不等于应该减速，持续限速可能妨碍已有自适应控制恢复原任务。

正常场景中三组结果完全相同；隐藏低摩擦场景中，仅运动组与视觉加运动组完全相同。相机没有提供外观变化线索时，本次实验没有产生额外视觉收益。下一步应改进异常原因区分与限速解除规则，再重复这些对照，不能仅凭轮体速度差减小就宣布控制更好。
