# MuJoCo 移动机器人在线适应仿真

本页路径相对于仓库根目录。命令示例从仓库根目录的 CMD 开始；第一次 cd 进入本阶段目录。依赖安装见[仓库说明](../README.md)。

这个版本将差速机器人放进 MuJoCo 物理仿真：底盘可以自由运动，左右轮通过铰链连接，电机施加扭矩，运动由重力、碰撞接触和轮地摩擦共同产生。交互窗口随物理仿真运行，不是先算完二维轨迹再播放。

本项目先使用本机 Windows Python 运行 MuJoCo。关于 Python 接口和交互窗口，可查阅 [MuJoCo 官方文档](https://mujoco.readthedocs.io/en/stable/python.html)。

## 第一次运行

1. 打开 `mujoco_ready`。
2. 双击 `start_mujoco.cmd`。
3. 程序先独立运行 16 秒正常物理数据，自动校准名义模型，再打开 MuJoCo 窗口，运行默认自适应控制。
4. 可以提前关闭窗口，程序会保存已经运行的数据；提前退出的结果标记为 `partial`，不能与完整实验直接比较。

启动器优先使用上一级目录的 `.venv\Scripts\python.exe`，找不到时调用命令行中的 `python`。依赖为 NumPy、Matplotlib 和 MuJoCo，版本范围见 `requirements.txt`。启动器本身不安装依赖或修改系统设置。窗口关闭后，终端会保留运行信息，按任意键退出。

## 命令行操作

在已经激活原虚拟环境的 CMD 中运行：

```cmd
cd /d mujoco_ready
python run_mujoco.py
```

先执行内置检查：

```cmd
python run_mujoco.py --self-check
```

运行不显示窗口的六方法对比：

```cmd
python run_mujoco.py --compare --headless
```

也可以双击 `run_compare.cmd`。它依次运行六种方法，生成日志、指标和总览图；计算时间取决于电脑性能。

选择场景或参考轨迹：

```cmd
python run_mujoco.py --scenario none --mode fixed
python run_mujoco.py --scenario left_motor_drop --mode adaptive
python run_mujoco.py --scenario low_friction --path straight --headless
python run_mujoco.py --path circle --duration 15
```

参数说明：

| 参数 | 含义 |
|---|---|
| `--headless` | 只计算和保存，不打开交互窗口 |
| `--snapshot` | 显式创建图像渲染器，额外保存 `mujoco_scene.png` |
| `--compare` | 在同一场景下依次比较六种方法 |
| `--mode fixed` | 固定模型加反馈控制 |
| `--mode pi` | 固定模型加积分反馈 |
| `--mode window_40` | 40 步，即 0.8 秒滑动窗口估计 |
| `--mode window_80` | 80 步，即 1.6 秒滑动窗口估计 |
| `--mode window_160` | 160 步，即 3.2 秒滑动窗口估计 |
| `--mode adaptive` | 根据近期变化缩短窗口，再逐渐加长 |
| `--scenario none` | 正常工况 |
| `--scenario left_motor_drop` | 运行中降低左电机实际输出扭矩 |
| `--scenario low_friction` | 运行中降低真实轮地接触摩擦参数 |
| `--path straight` / `--path circle` | 直线或圆形参考轨迹 |
| `--seed 3` | 指定测量噪声种子 |
| `--duration 15` | 设置实验时长，单位秒 |
| `--output-dir results_test` | 指定结果保存目录 |
| `--self-check` | 执行内置检查 |

控制与在线估计每 0.02 秒执行一次；MuJoCo 物理积分步长为 0.002 秒，因此一个控制周期内执行多个物理步。默认实验时长为 30 秒，第 8 秒开始施加扰动，用 2 秒逐渐达到目标变化量；具体参数以 `config.json` 为准。请先确认正常工况运行成功，再每次只调整一个因素。

`--headless` 默认完全不创建 OpenGL 窗口或图像渲染器，适合只做批量计算。需要物理场景截图时，使用 `python run_mujoco.py --headless --snapshot`；实时窗口模式结束时也会默认截图。截图需要可用的图形渲染环境。

## 模型与数据流

控制器发出的左右命令以牛为单位，表示期望轮缘驱动力；仿真接口用轮半径将其换算为牛·米扭矩。左电机输出降低等扰动在物理执行端施加。实际驱动由轮轴扭矩与轮地接触产生，同时另外施加平动、转动系数为 `[4, 0.8]` 的已知粘性阻力。控制器和在线估计器只能使用自己发出的原始命令与带噪观测，不能读取扰动缩放后的真实执行扭矩。实际扭矩、接触数据和真实状态用于审计与评分。

每个控制周期先用当前观测和当前估计计算命令、预测下一步运动，再执行物理步，最后根据新观测与预测之间的误差更新模型。更新后的参数从下一控制周期使用。

前面的简单二维模型不能直接视作 MuJoCo 机器人的精确方程。程序会另外采集正常物理运行的数据，自动校准控制器使用的名义模型，再开始扰动实验。正常校准与故障后的评分分开；这种模型逼近不意味着找回了全部真实物理参数。

`robot.xml` 中机器人总质量为 10 千克；一次正常校准得到的有效质量约为 10.209 千克、有效转动惯量约为 0.2234 千克·平方米。这是轮系和接触等影响下的预测模型系数，不等于 XML 中的真实质量、惯量。修改 `config.physics` 只改变预测器参数；修改真实机器人需要编辑 `robot.xml`，然后重新校准。

在线状态仍是显式左右有效效率 `z = [eta_left, eta_right]`，不是神经网络潜在变量。低摩擦通过实际接触参数实现，并检查混合后的接触摩擦；摩擦系数降低不等于电机效率降低，效率估计只能尝试吸收部分等效失配，不能当作摩擦系数测量结果。

## 输出和比较

程序打印结果目录，并保存 `.npz` 日志、`metrics.json`、`dashboard.png`、`config_used.json` 和正常工况校准记录 `calibration.json`。实时窗口模式或指定 `--snapshot` 时另存 `mujoco_scene.png`。保留配置和校准文件，便于重复同一组实验。

六种方法分别闭环运行，状态和控制输入会不同。可以比较同一任务下的轨迹误差、故障后恢复情况和控制输入；不能只凭不同闭环轨迹上的预测误差，断言哪个模型在同一批数据上更好。完整运行的轨迹误差键为 `position_rmse`；提前关窗时设置 `complete=false`，只保存 `partial_position_rmse`，并用 `score_interval_seconds` 标明实际评分区间。局部运行不能作为完整实验的分数。

第一版支持正常工况、左电机输出降低、低摩擦三种场景，没有实施载荷和坡度实验。MuJoCo 接触与摩擦仍是配置下的仿真模型，需要检查模型参数及运行结果后再扩展到实物。轮地抓地力或电机能力不足时，反馈与适应都可能无法恢复，不能预先保证自适应方法获胜。

## 已完成的检查与当前限制

正常、左电机输出降低、低摩擦场景各六种控制方法，以及圆形轨迹的六方法运行已完成。另做了物理步长减半检查：相同种子 1 下，固定与自适应方法的最大位置差约为 0.368 毫米。原生交互窗口也完成了约 2 秒启动和提前关闭检查，正常退出并保存 `partial` 结果。这些是当前配置下的运行和数值检查，不等于所有条件下的鲁棒性证明。

健康工况下，自适应估计存在噪声偏差，当前轨迹误差高于固定模型。默认低摩擦值 `mu = 0.08` 确实改变实际接触摩擦，但当前轨迹可能没有充分激发打滑，不能称为已经验证强滑移后的恢复。日志中的 `slip_proxy` 只是轮周速度与估计接触前向速度之差，不是标准滑移率。

## 启动失败时

保留终端中的完整报错，确认使用的是原项目虚拟环境，再运行 `python run_mujoco.py --self-check`。如果提示找不到 `mujoco`，检查该虚拟环境中是否已经安装 `requirements.txt` 对应的依赖。启动器不会自动下载或安装软件。
