# 移动机器人在线动特性适应仿真

本页路径相对于仓库根目录。命令示例从仓库根目录的 CMD 开始；第一次 cd 进入本阶段目录。依赖安装见[仓库说明](../README.md)。

这是可以直接运行的二维差速机器人仿真。机器人在运行中遇到动力学变化，比较固定模型、积分反馈、三种固定平均窗口和自适应平均窗口的表现。程序先计算完整轨迹，再通过动画回放；它是 Python 数值仿真，不依赖 ROS、Gazebo 或其他物理引擎。

## 第一次运行

1. 打开 `simulation_ready`。
2. 双击 `start_simulation.cmd`。
3. 等待计算和图片生成，查看动画与终端中打印的输出目录。
4. 关闭动画窗口后，在终端按任意键退出。

启动器优先使用上一级目录的 `.venv\Scripts\python.exe`，找不到时使用命令行中的 `python`。它不会安装软件或更改系统设置。现有虚拟环境中的 NumPy 和 Matplotlib 即可运行；依赖范围写在 `requirements.txt` 中。

默认实验运行 30 秒，仿真步长 0.02 秒，第 8 秒降低左电机效率，跟踪直线。参考速度为 `v_ref(t) = 0.8 + 0.15 sin(0.6t)` 米/秒，通过缓慢变速提供加速度激励，也便于检查载荷变化。六种控制方法各自运行一个带测量噪声的闭环机器人。

## 在命令行运行

在你已经激活虚拟环境的 CMD 中输入：

```cmd
cd /d simulation_ready
python run_simulation.py
```

先检查程序和配置：

```cmd
python run_simulation.py --self-check
```

只计算并保存结果，跳过动画窗口：

```cmd
python run_simulation.py --no-animation
```

选择实验，例如左电机失效、圆形参考轨迹：

```cmd
python run_simulation.py --scenario left_motor_drop --path circle
```

双击 `run_batch.cmd` 会对所有场景各运行 10 个噪声种子，保存批量结果，不显示动画。运行时间取决于电脑性能。等价命令是：

```cmd
python run_simulation.py --all-scenarios --seeds 10 --no-animation
```

常用参数：

| 参数 | 作用 |
|---|---|
| `--config config.json` | 使用指定配置文件 |
| `--scenario none` | 不施加扰动，检查正常工况 |
| `--scenario left_motor_drop` | 左电机效率在运行中降低 |
| `--scenario payload` | 质量和转动惯量同步增大 |
| `--scenario slope` | 加入沿世界坐标 x 方向的坡度重力，建议使用直线轨迹 |
| `--scenario traction_limit` | 限制每个车轮可以传递的驱动力 |
| `--path straight` / `--path circle` | 选择参考轨迹 |
| `--seed 3` | 指定单次实验的噪声种子 |
| `--seeds 10` | 从指定起始种子运行连续 10 次实验 |
| `--all-scenarios` | 遍历所有扰动场景 |
| `--no-animation` | 不显示回放，适合批量实验 |
| `--output-dir results_test` | 指定结果保存目录 |
| `--self-check` | 执行内置检查 |

修改 `config.json` 可以调整仿真时长、扰动、测量噪声和控制参数。建议先保留默认设置，确认程序正常运行，再每次只改一个因素。配置项的具体名称以文件内容为准。

## 如何看结果

每个场景与种子的结果目录保存六种方法各自的 `.npz` 轨迹日志，以及 `adaptive_trajectory.csv`、指标 `metrics.json`、实际使用的配置 `config_used.json` 和总览图 `dashboard.png`。输出根目录还保存 `summary.json`。以终端打印的路径为准。六种方法为：

| 方法 | 使用的信息 |
|---|---|
| `fixed` | 固定标称模型加反馈控制 |
| `pi` | 固定标称模型加积分反馈 |
| `window_40` | 最近 40 步，即 0.8 秒的数据 |
| `window_80` | 最近 80 步，即 1.6 秒的数据 |
| `window_160` | 最近 160 步，即 3.2 秒的数据 |
| `adaptive` | 根据近期变化迹象缩短窗口，随后逐渐加长 |

所有估计器都每 0.02 秒更新。平均窗口越长，通常越平稳，但旧数据也会使故障后的响应变慢。自适应窗口试图在这两者之间折中，是否有效需要查看当前实验结果。

优先比较轨迹误差、扰动后的恢复时间、控制输入饱和率，再查看效率估计和窗口长度。这里的“恢复”要求位置误差不超过 0.05 米、航向误差不超过 2 度、速度误差不超过 0.05 米/秒，三个条件同时保持 1 秒。记录首次满足该保持条件的确认时刻相对扰动时刻的时间，包含这 1 秒保持过程。首次恢复不代表此后一直稳定，还应查看 `in_band_fraction_after_change`，即扰动后三项条件同时达标的时间比例。扰动后一直达标记为 `0`，并标记 `remained_in_band`；出带后到实验结束仍未恢复记为 `null`。批量比较保留失败次数，不能只比较成功实验的平均时间。

六种方法各自闭环控制，得到的轨迹与控制输入不同。可以直接比较它们完成同一轨迹任务的效果；跨控制方法的预测误差不能单独作为“同一批数据下哪个模型更好”的结论。程序在每次运行中还用同一组观测和输入计算固定标称模型的影子预测（nominal shadow）：可以将该次运行的自适应预测与该次的影子预测比较，因为两者使用相同日志；不同控制方法之间依然不是同一批数据。

## 程序如何在线更新

每一步按以下顺序计算：

1. 接收当前带噪声的速度、角速度等观测。
2. 用当前模型计算控制输入，并预测下一步运动。
3. 仿真机器人执行输入，生成新的真实状态和新观测。
4. 对比新观测与刚才的预测，用残差和历史数据更新估计。
5. 更新后的估计从下一步开始使用。

真实状态和实际扰动只用于机器人仿真与结果评分，不提供给在线估计器。小输入时暂停该侧的效率估计，避免除以很小的数放大噪声。估计效率会裁剪后用于控制，日志同时保留原始估计与实际使用值。

自适应方法的状态是显式的 `z = [eta_left, eta_right]`，表示左右有效驱动力效率，不是神经网络学习的潜在变量。变化检测使用预先给定的速度、角速度测量噪声标定值；闭环控制输入和观测噪声相关，所以检测阈值只是工程启发式，不具有外生输入实验中“四倍标准差”的概率保证。报警后短窗口的检测盲段中，估计器仍持续更新。

## 这些实验能说明什么

电机效率变化与模型参数直接对应，适合先验证在线估计是否工作。对于载荷、坡度等变化，效率估计可能吸收部分等效模型失配，不能据此声称恢复了真实质量、摩擦系数或坡度。载荷变化需要变速产生加速度激励，恒速直线段本身不能充分揭示质量变化。

`traction_limit` 仅将左右轮的力分别限制在 `±mu * m * g / 2`，没有模拟轮胎转动、接触或侧滑，不能当作高保真轮胎打滑仿真。默认 `mu = 0.025` 时，总驱动力上限为 2.4525 牛；线性阻力系数为 4 牛·秒/米，因此平地稳态最高速度约为 0.613 米/秒，低于参考速度最低值 0.65 米/秒。这是物理上无法持续跟踪参考的压力测试，不能把不恢复归因于算法。可以调高配置中的 `mu`，另外检查驱动力足够时的可达条件。坡度场景采用沿世界坐标 x 方向的重力投影，并假设机器人没有侧滑。

如果剩余电机能力不足、牵引力上限过低，或者扰动不能用左右效率表示，机器人可能无法恢复。应同时查看输入饱和率与失败次数；程序不保证自适应方法在所有场景中获胜。更长窗口、更漂亮的估计曲线，也不能代替闭环轨迹性能验证。

## 如果没有启动

终端会保留错误信息。先确认上一级目录存在 `.venv\Scripts\python.exe`，再在该虚拟环境中运行 `python run_simulation.py --self-check`。如果提示缺少 NumPy 或 Matplotlib，先确认使用的是原来的虚拟环境；启动器不会自动安装依赖。请保留完整报错内容用于定位问题。
